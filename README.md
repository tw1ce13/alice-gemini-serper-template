# Яндекс Алиса + Gemini + Serper на Vercel

Готовый шаблон вебхука для навыка Яндекс Алисы. Вам не нужно редактировать код: разместите этот репозиторий в Vercel, добавьте два API-ключа и укажите адрес вебхука в Яндекс Диалогах.

## Самый простой способ — Fork

1. На GitHub нажмите **Fork** и создайте свою копию репозитория.
2. Откройте https://vercel.com/dashboard и нажмите **Add New… → Project**.
3. В списке **Import Git Repository** выберите свою копию и нажмите **Import**.
4. Нажмите **Deploy** и дождитесь завершения первого развёртывания.
5. В проекте Vercel откройте **Settings → Environment Variables**.
6. Создайте переменные окружения ниже, выбрав **Production** для каждой:
   - **Key:** GEMINI_API_KEY — **Value:** ключ из Google AI Studio: https://aistudio.google.com/app/apikey
   - **Key:** SERPER_API_KEY — **Value:** ключ из Serper: https://serper.dev
7. После сохранения ключей откройте **Deployments** и выберите **Redeploy** для последнего Production-развёртывания. Дождитесь статуса **Ready**.
8. В Vercel откройте **Settings → Domains**, скопируйте свой домен и добавьте в конец /api. Например: https://YOUR-PROJECT.vercel.app/api.
9. Откройте свой навык в Яндекс Диалогах. В настройках Backend вставьте этот полный адрес в **Webhook URL** и сохраните изменения.
10. В **Основные настройки → Хранилище** выберите **Использовать хранилище данных в навыке**, чтобы навык помнил контекст разговора и возвращающихся пользователей.

Названия разделов могут немного отличаться при обновлении интерфейса. Используйте только свой домен Vercel — не копируйте адрес автора шаблона.

## Если вы скачали ZIP

1. Распакуйте ZIP двойным кликом.
2. В своём GitHub нажмите **+ → New repository** и создайте репозиторий.
3. Откройте его и выберите **Add file → Upload files**.
4. Перетащите содержимое распакованной папки в браузер. Не потеряйте папку api и файл api/index.js внутри неё.
5. Нажмите **Commit changes**.
6. Вернитесь к шагу 2 в разделе выше и импортируйте репозиторий в Vercel.

## Какие ключи нужны

- **GEMINI_API_KEY** обязателен для ответов нейросети.
- **SERPER_API_KEY** включает поиск в интернете. Если он не задан, обычные ответы Gemini всё равно работают, но поиск недоступен.
- **GEMINI_MODEL** необязателен. По умолчанию используется gemini-3.5-flash-lite. Если эта модель недоступна для вашего API-ключа, укажите точное имя другой доступной модели Gemini.

Ключи вводятся только в **Vercel → Settings → Environment Variables**. Не размещайте их в исходном коде, GitHub, README, Яндекс Диалогах или сообщениях. Если ключ попал в открытый доступ, отзовите его и создайте новый.

## Как проверить навык — без команд и программирования

**Самый простой способ — проверить его голосом на колонке или через приложение с Алисой.**

1. Убедитесь, что в Яндекс Диалогах у навыка указан ваш адрес Vercel в поле **Webhook URL**, который заканчивается на `/api`.
2. В настройках навыка выберите тип доступа **Приватный** и сделайте навык доступным для тестирования. Для голосового запуска войдите на колонке или в приложении с Алисой в тот же аккаунт Яндекса, которым вы пользуетесь в консоли разработчика.
3. Скажите: **«Алиса, запусти навык [название или активационное имя вашего навыка]»**. Например, вместо скобок произнесите настоящее название, которое вы указали в настройках навыка.
4. Когда Алиса запустит навык, задайте обычный вопрос и проверьте, что она отвечает.

Если Алиса не находит навык или вы ещё не сделали его доступным для голосового запуска, откройте Яндекс Диалоги → свой навык → **Тестирование**. Этот встроенный тестер подходит для первой проверки до публикации и показывает ответ навыка.

Если всё работает в тестере, но не работает через колонку, проверьте, что навык доступен для голосового запуска, на колонке выбран тот же аккаунт Яндекса и произносится правильное активационное имя. Инструкция Яндекса: https://yandex.ru/dev/dialogs/alice/doc/ru/test

## Если навык не отвечает

1. Проверьте, что имена переменных написаны без опечаток и выбрано окружение **Production**.
2. После изменения ключей выполните **Redeploy** и дождитесь статуса **Ready**.
3. Проверьте правильность **Webhook URL**: домен должен быть вашим, путь должен заканчиваться на /api.
4. Откройте последнее развёртывание в Vercel и проверьте логи. Перед отправкой логов в ChatGPT удалите из них секретные данные.
5. Если ошибка появляется только при включённом хранилище данных, значит навык возвращает слишком большой объект состояния — смотрите раздел «Что навык запоминает».

## Что навык запоминает

После включения хранилища навык использует все три разреза состояния Яндекс Диалогов.

- **Внутри разговора** (`session_state`) — последние реплики, чтобы понимать уточнения вроде «а на выходных?».
- **Для устройства или приложения** (`application_state`) — работает всегда, даже без входа в Яндекс ID. Хранит имя, число разговоров и несколько недавних тем.
- **Для аккаунта Яндекс ID** (`user_state_update`) — то же самое, но переносится между колонкой, телефоном и браузером. Яндекс присылает этот разрез только авторизованным пользователям, поэтому навык пишет в оба и сам выбирает доступный.

Что это даёт в разговоре:

- Скажите «меня зовут Никита» — при следующем запуске навык поздоровается по имени.
- Если имени нет, навык напомнит последнюю тему: «в прошлый раз мы говорили про…».
- Скажите «забудь всё» или «очисти память», чтобы стереть сохранённые данные.
- Скажите «хватит», «пока» или «до свидания», чтобы корректно закрыть навык.

Важно: Яндекс отклоняет ответ, если любой из объектов состояния больше **1 КБ**, и в консоли это выглядит как ошибка сервера. Русский текст в UTF-8 занимает два байта на символ, поэтому шаблон считает размер состояния в байтах и обрезает историю с запасом — сначала отбрасываются самые старые реплики. Если вы меняете код, не складывайте в состояние много текста: это главная причина ошибки сервера при включённом хранилище.

## Ограничение времени ответа

Яндекс Диалоги ожидают ответ от навыка около 4,5 секунды. Поэтому шаблон ограничивает время поиска и генерации, чтобы не зависать на слишком долгом запросе. При медленном ответе Gemini сервер возвращает краткое сообщение о повторной попытке. Это помогает снизить число таймаутов, но не гарантирует полный ответ при медленной сети или высокой нагрузке.
